# ارزیاب هوشمند پایان‌نامه

اپلیکیشن فارسی (RTL) برای ارزیابی ساختارمند پایان‌نامه: فایل **Word (.docx)** یا **PDF** را آپلود
می‌کنید، متن به **Markdown** تبدیل و قابل دانلود می‌شود، سپس هوش مصنوعی متن را بر پایه‌ی یک
**قالب ارزیابی قابل تنظیم** (نام و وزن معیارها) ارزیابی می‌کند و یک گزارش قابل ارائه
(Markdown/JSON) می‌سازد. همه‌ی ارزیابی‌ها در سوابق قابل جستجو، فیلتر و بازبینی هستند و دسترسی با
ورود کاربر و مدیریت کاربران انجام می‌شود.

ساخته‌شده با **Next.js 14 (App Router) + TypeScript + Tailwind CSS** و قابل انتشار روی **Vercel**.

---

## قابلیت‌ها

- **ورود و مدیریت کاربران**: ورود با کوکی امضاشده و HTTP-only؛ مدیر می‌تواند کاربر بسازد، نقش و وضعیت را تغییر دهد، رمز را بازنشانی یا کاربر را حذف کند.
- **قالب‌های ارزیابی**: قالب پیش‌فرض ۸ معیاری، قالب‌های آماده‌ی مدیریت، علوم انسانی/مهندسی/پزشکی و امکان ویرایش، ساخت و نام‌گذاری قالب سفارشی با معیار و وزن دلخواه. قالب‌های سفارشی در مرورگر ذخیره می‌شوند.
- **فرم مشخصات سبک**: فقط عنوان پایان‌نامه، نام دانشجو و شماره تماس الزامی‌اند؛ بقیه‌ی فیلدها اختیاری‌اند و در صورت تکمیل اعتبارسنجی می‌شوند.
- **دستور تحلیل سفارشی**: در مرحله‌ی تحلیل می‌توانید چارچوب ارزیابی را تعیین کنید (مثلاً CIPP یا SWOT) یا از دستورهای آماده استفاده کنید؛ این دستور همراه گزارش ذخیره و صادر می‌شود.
- **تم روز/شب تمام‌صفحه**: سوییچ تم با ذخیره‌ی انتخاب کاربر در `localStorage` و اعمال پیش از رندر (بدون پرش رنگ).
- **رابط شیشه‌ای (Glassmorphism)**: سطوح شفاف، گرادیان نارنجی-کهربایی، بلور پس‌زمینه و طراحی RTL واکنش‌گرا.
- **صفحه‌ی «درباره ما»**: معرفی ابزار، معماری فنی، محدودیت‌ها و اعتبار طراح.
- **آپلود و تبدیل**: پشتیبانی از `.docx` (با mammoth) و PDF (با unpdf) همراه با بررسی امضای فایل (magic bytes) و سقف حجم ۱۰ مگابایت. فایل‌های بالای ۴ مگابایت با Vercel Blob مستقیماً از مرورگر آپلود می‌شوند تا محدودیت ۴.۵ مگابایتی بدنه‌ی Serverless دور زده شود.
- **پیش‌نمایش و دانلود Markdown** استخراج‌شده، همراه با آمار (تعداد کاراکتر، واژه و صفحات PDF).
- **ارزیابی هوشمند** با زنجیره‌ی مدل‌ها: مدل اصلی **DeepSeek** است و فقط در صورت شکست آن (و وجود کلید) مدل‌های رایگان OpenRouter امتحان می‌شوند.
- **نمره‌ی وزنی محاسبه‌شده در سرور** (نه از خروجی مدل) تا نتیجه قابل اتکا باشد.
- **گزارش ساختارمند**: نمره‌ی کل، نمره و وزن هر معیار، نقاط قوت/ضعف، خلاصه و پیشنهادهای اصلاحی.
- **خروجی MD/JSON + کپی سریع** برای استفاده در ایمیل، گزارش یا مستندسازی.
- **سوابق ارزیابی** با جستجو (عنوان/دانشجو/استاد/دانشگاه)، فیلتر مقطع و مرتب‌سازی بر اساس نمره یا تاریخ.
- **پنل شفافیت**: مدل استفاده‌شده، زمان تحلیل، تلاش‌های ناموفق و میزان کوتاه‌سازی متن.

## نصب و اجرا

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) ساخت فایل متغیرهای محیطی
copy .env.example .env.local    # ویندوز
# cp .env.example .env.local    # مک/لینوکس

# ۳) کلید DeepSeek را در .env.local بگذارید (مدل اصلی ارزیابی)
#    DEEPSEEK_API_KEY=sk-...
#    OPENROUTER_API_KEY=...   (اختیاری، فقط جایگزین)

# ۳.۵) صحت کلید را بدون بالا آوردن برنامه بررسی کنید
npm run ai:check

# ۴) اجرای محیط توسعه
npm run dev        # http://localhost:3000

# ۵) بررسی تایپ‌ها و build تولیدی
npm run typecheck
npm run build
npm run start
```

> هیچ کلیدی داخل کد نیست؛ همه از `process.env` خوانده می‌شوند و `.env.local` در `.gitignore` قرار دارد.

### ورود اولیه

در اولین اجرا، اگر هنوز کاربری وجود نداشته باشد یک مدیر ساخته می‌شود:

- نام کاربری پیش‌فرض: `admin`
- رمز عبور پیش‌فرض: `admin123`

این مقادیر فقط برای اجرای محلی است. پیش از استقرار، `ADMIN_USERNAME`، `ADMIN_PASSWORD` و
`AUTH_SECRET` را تنظیم کنید. رمز مدیر را می‌توانید از صفحه‌ی **مدیریت کاربران → تغییر رمز حساب من**
عوض کنید.

## متغیرهای محیطی

| متغیر | الزامی | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `DEEPSEEK_API_KEY` | **بله** | — | مدل اصلی ارزیابی؛ بدون آن تحلیل انجام نمی‌شود |
| `OPENROUTER_API_KEY` | خیر | — | اختیاری؛ مدل‌های رایگان OpenRouter فقط پس از شکست DeepSeek امتحان می‌شوند |
| `DEEPSEEK_BASE_URL` | خیر | `https://api.deepseek.com` | آدرس API دیپ‌سیک |
| `DEEPSEEK_MODEL` | خیر | `deepseek-chat` | نام مدل دیپ‌سیک |
| `AUTH_SECRET` | **بله در Production** | مقدار توسعه | کلید امضای کوکی نشست؛ حتماً یک رشته‌ی تصادفی طولانی باشد |
| `ADMIN_USERNAME` | خیر | `admin` | نام کاربری مدیر اولیه (فقط در اولین اجرا) |
| `ADMIN_PASSWORD` | **بله در Production** | `admin123` | رمز مدیر اولیه (حداقل ۸ کاراکتر) |
| `ADMIN_DISPLAY_NAME` | خیر | `مدیر سامانه` | نام نمایشی مدیر اولیه |
| `OPENROUTER_FREE_MODELS` | خیر | کشف خودکار | فهرست مدل‌های رایگان با کاما |
| `AI_MAX_INPUT_CHARS` | خیر | `24000` | حداکثر کاراکتر ارسالی به مدل |
| `AI_MAX_OUTPUT_TOKENS` | خیر | `6000` | سقف توکن خروجی مدل (۱۰۰۰ تا ۸۱۹۲)؛ کوچک‌بودن آن باعث قطع‌شدن JSON می‌شود |
| `AI_TOTAL_BUDGET_MS` | خیر | `55000` | بودجه‌ی زمانی کل تحلیل |
| `FREE_MODEL_TIMEOUT_MS` | خیر | `20000` | مهلت هر مدل رایگان |
| `AI_DEEPSEEK_RESERVE_MS` | خیر | `20000` | زمان رزرو‌شده برای DeepSeek |

\* بدون `DEEPSEEK_API_KEY` تحلیل با پیام خطای شفاف متوقف می‌شود (تنها در صورتی که
`OPENROUTER_API_KEY` تنظیم شده باشد، تحلیل با مدل رایگان انجام می‌شود). صحت کلید را می‌توانید
بدون اجرای برنامه با `npm run ai:check` بررسی کنید.

### چرا پیام «کلید DeepSeek روی سرور خوانده نشد» می‌بینم؟

1. **سرور را ری‌استارت نکرده‌اید**: Next.js متغیرهای `.env.local` را فقط در زمان راه‌اندازی
   می‌خواند؛ پس از افزودن کلید، `npm run dev` را متوقف و دوباره اجرا کنید.
2. **روی Vercel متغیر تنظیم نشده یا Redeploy نشده است**: پس از افزودن `DEEPSEEK_API_KEY` در
   Settings → Environment Variables، یک استقرار تازه لازم است؛ استقرارهای قبلی متغیر جدید را
   نمی‌بینند.
3. **متغیر برای محیط اشتباه تنظیم شده**: برای Production و Preview جدا (یا All Environments)
   تنظیم کنید.
4. برای تشخیص سریع، `GET /api/health` را باز کنید: `ai.ready` باید `true` باشد و
   `ai.deepseekModel` مدل استفاده‌شده را نشان می‌دهد.

### چرا پیام «پاسخ مدل ساختار JSON معتبر نداشت» می‌بینم؟

گزارش کامل (۵ نقطه قوت و ۵ نقطه ضعف برای هر معیار) در فارسی حجم زیادی دارد؛ اگر سقف
توکن خروجی کم باشد، پاسخ مدل وسط JSON قطع می‌شود و ساختار ناقص می‌ماند.

- سقف خروجی DeepSeek روی `6000` تنظیم شده است. اگر باز هم این پیام را دیدید،
  `AI_MAX_OUTPUT_TOKENS` را تا `8192` بالا ببرید و دوباره استقرار دهید.
- خروجی بریده‌شده در سرور بازیابی می‌شود (`lib/ai/json-recovery.ts`): بخش‌های کامل
  نگه داشته می‌شوند و معیارهای ناقص در گزارش با نمره‌ی میانگین و یادداشت شفاف مشخص می‌شوند.
- برای دیدن علت دقیق، لاگ سرور را ببینید: خط `[ai] ... به سقف ... توکن خروجی رسید`
  یعنی پاسخ بریده شده و خط `[ai] خروجی مدل JSON معتبر نبود ...` انتهای خروجی را نشان می‌دهد.

## چطور کار می‌کند؟

1. **مشخصات** (عنوان، نام دانشجو و شماره تماس الزامی؛ مقطع، دانشگاه، استاد راهنما و … اختیاری) در فرم وارد و در کلاینت و سرور اعتبارسنجی می‌شود.
2. **آپلود** فایل به `/api/convert`؛ فایل‌های تا ۴ مگابایت مستقیم در بدنه‌ی درخواست و فایل‌های بزرگ‌تر (تا ۱۰ مگابایت) با Vercel Blob مستقیماً از مرورگر آپلود می‌شوند. سرور نوع فایل را از پسوند و MIME و امضای بایت‌ها تشخیص می‌دهد، حجم را
   می‌سنجد و متن را به Markdown تبدیل می‌کند.
3. **تحلیل** با ارسال Markdown به `/api/analyze`؛ متن در صورت نیاز فشرده می‌شود، مدل فراخوانی و پاسخ
   اعتبارسنجی/نرمال‌سازی می‌شود و نمره‌ی نهایی از وزن‌های `lib/criteria.ts` محاسبه می‌شود.
4. **گزارش** نمایش داده می‌شود و می‌توانید آن را به Markdown یا JSON دانلود یا کپی کنید.
5. **بایگانی**: رکورد (مشخصات + متن کوتاه‌شده + گزارش + اطلاعات مدل) در KV ذخیره می‌شود؛ اگر KV تنظیم
   نباشد، در `localStorage` مرورگر نگه داشته می‌شود.

## قالب‌های ارزیابی

قالب پیش‌فرض همان هشت معیار قبلی است:

| معیار | وزن |
| --- | --- |
| اصالت و نوآوری | ۱۵٪ |
| مرور ادبیات و پیشینه پژوهش | ۱۰٪ |
| وضوح بیان مسئله و اهداف | ۱۰٪ |
| متدولوژی و روش پژوهش | ۲۰٪ |
| تحلیل داده‌ها و نتایج | ۱۵٪ |
| بحث و نتیجه‌گیری | ۱۰٪ |
| کیفیت نگارش و ساختار | ۱۰٪ |
| منابع و ارجاعات | ۱۰٪ |

قالب‌های آماده‌ی «مدیریت»، «علوم انسانی و اجتماعی»، «مهندسی و فناوری» و «علوم پزشکی و سلامت» هر کدام ۹ معیار
دارند. در گام اول ویزارد می‌توانید عنوان و وزن هر معیار را تغییر دهید، معیار جدید اضافه کنید و
قالب را با یک نام دلخواه در مرورگر ذخیره کنید. قالب‌های سفارشی به کاربر/مرورگر وابسته‌اند.

اعتبارسنجی و تعریف قالب‌ها در `lib/templates.ts` است؛ نمره‌ی کل در سرور و به‌صورت میانگین وزنی
(بر مجموع وزن‌ها) محاسبه می‌شود.

## API

| متد | مسیر | ورودی | خروجی |
| --- | --- | --- | --- |
| `POST` | `/api/convert` | `multipart/form-data` با فیلد `file` یا `{ blobPathname, fileName }` | `{ markdown, info }` |
| `POST` | `/api/blob/upload` | بدنه‌ی استاندارد Client Upload در Vercel Blob | توکن آپلود مستقیم |
| `POST` | `/api/analyze` | `{ markdown, meta, instructions?, template? }` | `{ report, analysis, template }` |
| `POST` | `/api/auth/login` | `{ username, password }` | `{ user }` + کوکی نشست |
| `POST` | `/api/auth/logout` | — | `{ ok }` |
| `GET` | `/api/auth/me` | — | `{ user }` |
| `PATCH` | `/api/auth/password` | `{ currentPassword, newPassword }` | `{ ok }` |
| `GET/POST` | `/api/users` | — / اطلاعات کاربر جدید | فهرست/کاربر ساخته‌شده (فقط مدیر) |
| `PATCH/DELETE` | `/api/users/[id]` | نقش/وضعیت/رمز / — | کاربر ویرایش‌شده / `{ ok }` (فقط مدیر) |
| `GET` | `/api/history` | — | `{ backend, persistent, items[] }` |
| `POST` | `/api/history` | رکورد کامل ارزیابی | `{ backend, stored }` |
| `GET` | `/api/history/[id]` | — | `{ backend, record }` |
| `DELETE` | `/api/history/[id]` | — | `{ backend, deleted }` |
| `GET` | `/api/health` | — | وضعیت محیط اجرا (نسخه Node، Web Crypto، منبع راز نشست، KV، کلیدها) |

همه‌ی مسیرها به‌جز `/login`، `/about`، `/api/auth/login`، `/api/auth/logout`، `/api/auth/me` و `/api/health` نیازمند نشست هستند. خطاها با ساختار یکسان
`{ error, fieldErrors?, attempts? }` و کد وضعیت مناسب برمی‌گردند.

## استقرار روی Vercel

1. مخزن را به GitHub push کنید و در [vercel.com](https://vercel.com) پروژه را Import کنید (تنظیمات
   پیش‌فرض Next.js کافی است).
2. در **Settings → Environment Variables** مقدار `DEEPSEEK_API_KEY` را برای محیط‌های Production و
   Preview تنظیم کنید (مدل اصلی). `OPENROUTER_API_KEY` اختیاری است. پس از افزودن متغیرها حتماً
   **Redeploy** کنید؛ استقرار فعلی متغیرهای جدید را نمی‌بیند.
3. مقادیر `AUTH_SECRET` (رشته‌ی تصادفی طولانی)، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را تنظیم کنید.
4. برای سوابق و کاربران دائمی از **Storage / Marketplace** یک دیتابیس **Upstash Redis** متصل کنید؛
   متغیرهای `KV_REST_API_URL` و `KV_REST_API_TOKEN` خودکار اضافه می‌شوند و کاربران هم در KV ذخیره
   می‌شوند. بدون KV، ذخیره‌سازی کاربران روی فایل محلی است که در Vercel پایدار نیست (با این حال ورود مدیر
   در چند Function مجزا با امضای کوکی کار می‌کند).
5. برای امکان آپلود فایل‌های **بالای ۴ مگابایت تا ۱۰ مگابایت**، از **Storage → Create → Blob** یک
   Blob Store با دسترسی **Private** بسازید و به پروژه متصل کنید. اتصال Store متغیر
   `BLOB_READ_WRITE_TOKEN` را خودکار به محیط پروژه اضافه می‌کند؛ برای اجرای محلی همان مقدار را در
   `.env.local` بگذارید. فایل موقت پس از تبدیل از Blob حذف می‌شود.
6. Deploy کنید. مسیرهای `/api/analyze` و `/api/convert` با `maxDuration = 60` اجرا می‌شوند؛ در پلن
   Hobby این سقف رعایت شده است.

## عیب‌یابی ورود روی Vercel

اگر پس از استقرار، صفحه‌ی ورود باز نشد یا ورود انجام نشد، این ترتیب را بررسی کنید:

1. **وضعیت محیط**: `https://<domain>/api/health` را باز کنید. اگر پاسخ نداد یا `status` برابر
   `ok` نبود، مشکل از استقرار است؛ لاگ را در Vercel → Deployments → Functions ببینید.
2. `auth.webCrypto` باید `true` باشد. اگر `false` بود یعنی Node قدیمی (۱۸) بدون Web Crypto global
   اجرا شده است؛ `engines.node` در `package.json` روی `22.x` تنظیم شده و پس از Redeploy درست می‌شود.
3. `auth.secretSource` باید `AUTH_SECRET` (یا دست‌کم `ADMIN_PASSWORD`) باشد. مقدار `fallback`
   یعنی هیچ‌کدام تنظیم نشده‌اند و با هر Redeploy کوکی‌های قبلی بی‌اعتبار می‌شوند.
4. `auth.adminPasswordConfigured` و `auth.adminPasswordLongEnough` را ببینید؛ رمز کوتاه‌تر از ۸
   کاراکتر نادیده گرفته می‌شود و رمز پیش‌فرض `admin123` به کار می‌رود.
5. اگر صفحه‌ی ورود به‌جای فرم خطای ۵۰۰ می‌دهد: Middleware و RootLayout اصلاح شده‌اند تا خطای
   بررسی نشست کل سایت را از کار نیندازد؛ لاگ‌های `[middleware]`، `[layout]` و `[api/auth/login]`
   علت دقیق را نشان می‌دهند.
6. اگر ورود موفق است اما بلافاصله به `/login` برمی‌گردید، کوکی نشست ذخیره نشده است: حالت ناشناس،
   مسدودکننده‌ی کوکی و HTTPS را بررسی کنید. برای کاربران پایدار بین Functionها، KV را وصل کنید.
7. اگر روی دامنه‌ی Vercel صفحه‌ی «Log in to Vercel» دیده می‌شود، **Deployment Protection** روشن است؛
   آن را در Settings → Deployment Protection غیرفعال کنید.

## نگارش و املای فارسی

خروجی‌ها در سه لایه از نظر املا و فاصله‌گذاری اصلاح می‌شوند:

1. **دستور مدل** (`lib/ai/prompt.ts`): مدل موظف است با «ی/ک» فارسی، نیم‌فاصله‌ی درست («می‌شود»، «داده‌ها»،
   «دقیق‌تر»، «مهم‌ترین») و فاصله‌ی معمولی میان واژه‌ها بنویسد و از «می‌باشد / بطور / بخصوص / بکار» پرهیز کند.
2. **اصلاح خودکار** (`lib/persian.ts` → `polishPersianText`): فاصله‌های ویژه‌ی یونیکد و نویسه‌های نامرئی،
   چسبیدن فارسی/لاتین و جاافتادن فاصله پس از سجاوندی اصلاح می‌شود؛ سپس نیم‌فاصله‌ی «می/نمی»، پسوندهای
   «ها/های/تر/ترین»، «ه‌ی/ه‌ای» و غلط‌های پربسامد («پایان نامه»، «بطور»، «می‌باشد»، …) درست می‌شود.
   فهرست فعل‌های مجاز بسته است تا واژه‌هایی مانند «میدان»، «میزان» و «میلیون» به‌اشتباه شکسته نشوند.
   ترکیب‌های نیم‌فاصله‌دار («جمع بندی»، «نتیجه گیری»، …) هم از فهرست بسته خوانده می‌شوند تا عبارت‌هایی
   مانند «را برداری» یا «را آوری» به هم نچسبند.
3. **نمایش و خروجی** (`lib/report.ts` → `polishReport` و `polishPersianMarkdown`): گزارش‌های قدیمیِ ذخیره‌شده
   هم هنگام نمایش و در خروجی Markdown/JSON اصلاح می‌شوند. پیش‌نمایش متن خود پایان‌نامه فقط از نظر
   فاصله‌گذاری پاک‌سازی می‌شود و نوشته‌ی کاربر بازنویسی نمی‌شود.

بازسازی پاراگراف‌ها هم حفظ می‌شود.

## محدودیت‌ها و نکات مهم

- **حجم فایل تا ۱۰ مگابایت**: فایل‌های تا ۴ مگابایت مستقیم به `/api/convert` فرستاده می‌شوند؛ برای
  فایل‌های بزرگ‌تر Vercel Blob لازم است (جزئیات در بخش استقرار). بدون اتصال Blob، آپلود فایل‌های
  بزرگ‌تر از ۴ مگابایت با پیام راهنما رد می‌شود.
- **فرمت‌های پشتیبانی‌شده**: `.docx` و `.pdf`. فایل‌های قدیمی `.doc` و PDFهای اسکن‌شده (بدون لایه‌ی متنی)
  متن قابل استخراج ندارند.
- **بدون KV، سوابق محلی هستند**: داده‌ها فقط در همان مرورگر/دستگاه می‌مانند، با پاک کردن داده‌های مرورگر
  از بین می‌روند و بین دستگاه‌ها همگام نمی‌شوند. متن ذخیره‌شده در سوابق برای صرفه‌جویی در فضا به ۳۰۰ هزار
  کاراکتر و تعداد رکوردهای محلی به ۲۰ عدد محدود شده است.
- **کاربران بدون KV**: در اجرای محلی در `.data/users.json` ذخیره می‌شوند. در محیط Serverless بدون KV،
  تغییرات کاربران پایدار نیست؛ برای Production حتماً KV تنظیم کنید.
- **قالب‌های سفارشی**: در `localStorage` مرورگر ذخیره می‌شوند و بین مرورگرها/دستگاه‌ها همگام نمی‌شوند.
  قالب استفاده‌شده در هر ارزیابی همراه گزارش و سوابق ثبت می‌شود.
- **دقت ارزیابی**: خروجی هوش مصنوعی جایگزین داوری رسمی انسانی نیست و باید به‌عنوان دستیار بازبینی استفاده شود.
- **مدل‌های رایگان**: ممکن است کند یا موقتاً در دسترس نباشند؛ برنامه به‌طور خودکار به مدل جایگزین
  سوییچ می‌کند و همه‌ی تلاش‌ها را در بخش شفافیت گزارش نشان می‌دهد.
