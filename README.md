# ارزیاب هوشمند پایان‌نامه

اپلیکیشن فارسی (RTL) برای ارزیابی ساختارمند پایان‌نامه: فایل **Word (.docx)** یا **PDF** را آپلود
می‌کنید، متن به **Markdown** تبدیل و قابل دانلود می‌شود، سپس هوش مصنوعی متن را بر پایه‌ی یک
**قالب ارزیابی قابل تنظیم** (نام و وزن معیارها) ارزیابی می‌کند و یک گزارش قابل ارائه
(Markdown/JSON) می‌سازد. همه‌ی ارزیابی‌ها در سوابق قابل جستجو، فیلتر و بازبینی هستند و دسترسی با
ورود کاربر و مدیریت کاربران انجام می‌شود.

ساخته‌شده با **Next.js 14 (App Router) + TypeScript + Tailwind CSS** و قابل انتشار روی **Vercel**.

---

## قابلیت‌ها

- **ورود و مدیریت کاربران**: ورود با کوکی امضاشده و HTTP-only؛ مدیر می‌تواند کاربر بسازد، نقش و وضعیت را تغییر دهد، رمز را بازنشانی یا کاربر را حذف کند.
- **قالب‌های ارزیابی**: قالب پیش‌فرض ۸ معیاری، قالب‌های آماده‌ی مدیریت، علوم انسانی/مهندسی/پزشکی و امکان ویرایش، ساخت و نام‌گذاری قالب سفارشی با معیار و وزن دلخواه. قالب‌های سفارشی در مرورگر ذخیره می‌شوند.
- **فرم مشخصات سبک**: فقط عنوان پایان‌نامه، نام دانشجو و شماره تماس الزامی‌اند؛ بقیه‌ی فیلدها اختیاری‌اند و در صورت تکمیل اعتبارسنجی می‌شوند.
- **دستور تحلیل سفارشی**: در مرحله‌ی تحلیل می‌توانید چارچوب ارزیابی را تعیین کنید (مثلاً CIPP یا SWOT) یا از دستورهای آماده استفاده کنید؛ این دستور همراه گزارش ذخیره و صادر می‌شود.
- **تم روز/شب تمام‌صفحه**: سوییچ تم با ذخیره‌ی انتخاب کاربر در `localStorage` و اعمال پیش از رندر (بدون پرش رنگ).
- **رابط شیشه‌ای (Glassmorphism)**: سطوح شفاف، گرادیان نارنجی-کهربایی، بلور پس‌زمینه و طراحی RTL واکنش‌گرا.
- **صفحه‌ی «درباره ما»**: معرفی ابزار، معماری فنی، محدودیت‌ها و اعتبار طراح.
- **آپلود و تبدیل**: پشتیبانی از `.docx` (با mammoth) و PDF (با unpdf) همراه با بررسی امضای فایل (magic bytes) و سقف حجم ۴ مگابایت.
- **پیش‌نمایش و دانلود Markdown** استخراج‌شده، همراه با آمار (تعداد کاراکتر، واژه و صفحات PDF).
- **ارزیابی هوشمند** با زنجیره‌ی مدل‌ها: ابتدا مدل‌های رایگان OpenRouter و در صورت شکست، **DeepSeek** به‌عنوان جایگزین.
- **نمره‌ی وزنی محاسبه‌شده در سرور** (نه از خروجی مدل) تا نتیجه قابل اتکا باشد.
- **گزارش ساختارمند**: نمره‌ی کل، نمره و وزن هر معیار، نقاط قوت/ضعف، خلاصه و پیشنهادهای اصلاحی.
- **خروجی MD/JSON + کپی سریع** برای استفاده در ایمیل، گزارش یا مستندسازی.
- **سوابق ارزیابی** با جستجو (عنوان/دانشجو/استاد/دانشگاه)، فیلتر مقطع و مرتب‌سازی بر اساس نمره یا تاریخ.
- **پنل شفافیت**: مدل استفاده‌شده، زمان تحلیل، تلاش‌های ناموفق و میزان کوتاه‌سازی متن.

## نصب و اجرا

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) ساخت فایل متغیرهای محیطی
copy .env.example .env.local    # ویندوز
# cp .env.example .env.local    # مک/لینوکس

# ۳) کلیدها را در .env.local بگذارید (حداقل یکی)
#    OPENROUTER_API_KEY=...
#    DEEPSEEK_API_KEY=...

# ۴) اجرای محیط توسعه
npm run dev        # http://localhost:3000

# ۵) بررسی تایپ‌ها و build تولیدی
npm run typecheck
npm run build
npm run start
```

> هیچ کلیدی داخل کد نیست؛ همه از `process.env` خوانده می‌شوند و `.env.local` در `.gitignore` قرار دارد.

### ورود اولیه

در اولین اجرا، اگر هنوز کاربری وجود نداشته باشد یک مدیر ساخته می‌شود:

- نام کاربری پیش‌فرض: `admin`
- رمز عبور پیش‌فرض: `admin123`

این مقادیر فقط برای اجرای محلی است. پیش از استقرار، `ADMIN_USERNAME`، `ADMIN_PASSWORD` و
`AUTH_SECRET` را تنظیم کنید. رمز مدیر را می‌توانید از صفحه‌ی **مدیریت کاربران → تغییر رمز حساب من**
عوض کنید.

## چطور کار می‌کند؟

1. **مشخصات** (عنوان، نام دانشجو و شماره تماس الزامی؛ مقطع، دانشگاه، استاد راهنما و … اختیاری) در فرم وارد و در کلاینت و سرور اعتبارسنجی می‌شود.
2. **آپلود** فایل به `/api/convert`؛ سرور نوع فایل را از پسوند و MIME و امضای بایت‌ها تشخیص می‌دهد، حجم را
   می‌سنجد و متن را به Markdown تبدیل می‌کند.
3. **تحلیل** با ارسال Markdown به `/api/analyze`؛ متن در صورت نیاز فشرده می‌شود، مدل فراخوانی و پاسخ
   اعتبارسنجی/نرمال‌سازی می‌شود و نمره‌ی نهایی از وزن‌های `lib/criteria.ts` محاسبه می‌شود.
4. **گزارش** نمایش داده می‌شود و می‌توانید آن را به Markdown یا JSON دانلود یا کپی کنید.
5. **بایگانی**: رکورد (مشخصات + متن کوتاه‌شده + گزارش + اطلاعات مدل) در KV ذخیره می‌شود؛ اگر KV تنظیم
   نباشد، در `localStorage` مرورگر نگه داشته می‌شود.

## قالب‌های ارزیابی

قالب پیش‌فرض همان هشت معیار قبلی است:

| معیار | وزن |
| --- | --- |
| اصالت و نوآوری | ۱۵٪ |
| مرور ادبیات و پیشینه پژوهش | ۱۰٪ |
| وضوح بیان مسئله و اهداف | ۱۰٪ |
| متدولوژی و روش پژوهش | ۲۰٪ |
| تحلیل داده‌ها و نتایج | ۱۵٪ |
| بحث و نتیجه‌گیری | ۱۰٪ |
| کیفیت نگارش و ساختار | ۱۰٪ |
| منابع و ارجاعات | ۱۰٪ |

قالب‌های آماده‌ی «مدیریت»، «علوم انسانی و اجتماعی»، «مهندسی و فناوری» و «علوم پزشکی و سلامت» هر کدام ۹ معیار
دارند. در گام اول ویزارد می‌توانید عنوان و وزن هر معیار را تغییر دهید، معیار جدید اضافه کنید و
قالب را با یک نام دلخواه در مرورگر ذخیره کنید. قالب‌های سفارشی به کاربر/مرورگر وابسته‌اند.

اعتبارسنجی و تعریف قالب‌ها در `lib/templates.ts` است؛ نمره‌ی کل در سرور و به‌صورت میانگین وزنی
(بر مجموع وزن‌ها) محاسبه می‌شود.

## API

| متد | مسیر | ورودی | خروجی |
| --- | --- | --- | --- |
| `POST` | `/api/convert` | `multipart/form-data` با فیلد `file` | `{ markdown, info }` |
| `POST` | `/api/analyze` | `{ markdown, meta, instructions?, template? }` | `{ report, analysis, template }` |
| `POST` | `/api/auth/login` | `{ username, password }` | `{ user }` + کوکی نشست |
| `POST` | `/api/auth/logout` | — | `{ ok }` |
| `GET` | `/api/auth/me` | — | `{ user }` |
| `PATCH` | `/api/auth/password` | `{ currentPassword, newPassword }` | `{ ok }` |
| `GET/POST` | `/api/users` | — / اطلاعات کاربر جدید | فهرست/کاربر ساخته‌شده (فقط مدیر) |
| `PATCH/DELETE` | `/api/users/[id]` | نقش/وضعیت/رمز / — | کاربر ویرایش‌شده / `{ ok }` (فقط مدیر) |
| `GET` | `/api/history` | — | `{ backend, persistent, items[] }` |
| `POST` | `/api/history` | رکورد کامل ارزیابی | `{ backend, stored }` |
| `GET` | `/api/history/[id]` | — | `{ backend, record }` |
| `DELETE` | `/api/history/[id]` | — | `{ backend, deleted }` |

همه‌ی مسیرها به‌جز `/login`، `/about`، `/api/auth/login`، `/api/auth/logout` و `/api/auth/me` نیازمند نشست هستند. خطاها با ساختار یکسان
`{ error, fieldErrors?, attempts? }` و کد وضعیت مناسب برمی‌گردند.

## استقرار روی Vercel

1. مخزن را به GitHub push کنید و در [vercel.com](https://vercel.com) پروژه را Import کنید (تنظیمات
   پیش‌فرض Next.js کافی است).
2. در **Settings → Environment Variables** مقادیر `OPENROUTER_API_KEY` و/یا `DEEPSEEK_API_KEY` را
   برای محیط‌های Production و Preview تنظیم کنید.
3. مقادیر `AUTH_SECRET` (رشته‌ی تصادفی طولانی)، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را تنظیم کنید.
4. برای سوابق و کاربران دائمی از **Storage / Marketplace** یک دیتابیس **Upstash Redis** متصل کنید؛
   متغیرهای `KV_REST_API_URL` و `KV_REST_API_TOKEN` خودکار اضافه می‌شوند و کاربران هم در KV ذخیره
   می‌شوند. بدون KV، ذخیره‌سازی کاربران روی فایل محلی است که در Vercel پایدار نیست.
5. Deploy کنید. مسیر `/api/analyze` با `maxDuration = 60` اجرا می‌شود؛ در پلن Hobby این سقف رعایت شده است.

## محدودیت‌ها و نکات مهم

- **حجم فایل تا ۴ مگابایت** (سقف بدنه‌ی درخواست در Vercel حدود ۴.۵ مگابایت است). برای فایل‌های
  بزرگ‌تر بهتر است متن را در چند بخش ارزیابی کنید.
- **فرمت‌های پشتیبانی‌شده**: `.docx` و `.pdf`. فایل‌های قدیمی `.doc` و PDFهای اسکن‌شده (بدون لایه‌ی متنی)
  متن قابل استخراج ندارند.
- **بدون KV، سوابق محلی هستند**: داده‌ها فقط در همان مرورگر/دستگاه می‌مانند، با پاک کردن داده‌های مرورگر
  از بین می‌روند و بین دستگاه‌ها همگام نمی‌شوند. متن ذخیره‌شده در سوابق برای صرفه‌جویی در فضا به ۳۰۰ هزار
  کاراکتر و تعداد رکوردهای محلی به ۲۰ عدد محدود شده است.
- **کاربران بدون KV**: در اجرای محلی در `.data/users.json` ذخیره می‌شوند. در محیط Serverless بدون KV،
  تغییرات کاربران پایدار نیست؛ برای Production حتماً KV تنظیم کنید.
- **قالب‌های سفارشی**: در `localStorage` مرورگر ذخیره می‌شوند و بین مرورگرها/دستگاه‌ها همگام نمی‌شوند.
  قالب استفاده‌شده در هر ارزیابی همراه گزارش و سوابق ثبت می‌شود.
- **دقت ارزیابی**: خروجی هوش مصنوعی جایگزین داوری رسمی انسانی نیست و باید به‌عنوان دستیار بازبینی استفاده شود.
- **مدل‌های رایگان**: ممکن است کند یا موقتاً در دسترس نباشند؛ برنامه به‌طور خودکار به مدل جایگزین
  سوییچ می‌کند و همه‌ی تلاش‌ها را در بخش شفافیت گزارش نشان می‌دهد.
